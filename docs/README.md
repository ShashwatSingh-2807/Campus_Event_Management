## How to read the specifications

1. Start with the PRD to understand the problem, users, goals, and release scope.
2. Read the TRD to understand the proposed architecture and engineering constraints.
3. Read the Application Flow to understand how users move through the product.
4. Use the planned database and API documents as implementation-level references once they are created.

## Status conventions

- **Draft baseline:** A working specification agreed for initial planning; subject to revision.
- **Approved:** Reviewed and accepted as the current implementation reference.
- **Implemented:** The relevant behavior has been built and verified.

A documented requirement is not evidence that the feature has already been implemented.
